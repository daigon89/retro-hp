# Sales Dashboard Web App - プロダクト仕様書

## 前提条件

- **プラットフォーム**: Webアプリケーション（ブラウザで動作）
- **認証**: ログイン機能を持ち、管理者と営業担当者を区別する
- **データ入力**: 本アプリはデータの閲覧・分析専用。データ入力は引き続き Google スプレッドシート上で行う
- **言語**: UI は日本語
- **デプロイ**: ローカル起動可能な状態を最低限とし、クラウドデプロイは非ゴールとする

---

## 1. プロダクト概要

- **名称**: Sales Watch
- **一言ピッチ**: 重いスプレッドシートの営業ダッシュボードを、瞬時に表示される専用 Web アプリに置き換える
- **想定ユーザー**: 営業チームの管理者および営業担当者（約35名）
- **中核的な価値提案**: スプレッドシートでは数十秒かかる集計・フィルタリング操作が1秒以内で完了し、どの端末からでも快適に営業 KPI を把握できる

---

## 2. ゴールと非ゴール

### ゴール

1. Google スプレッドシートの既存ダッシュボード（月別サマリー、担当者別、イベント別、導線別、クロス集計、各一覧）をすべて Web アプリで再現する
2. スプレッドシートから自動的にデータを取得し、手動のデータ移行作業を不要にする
3. あらゆる集計ビューの表示を2秒以内に完了させる
4. 管理者と担当者で適切にアクセスを分ける認証・認可を実現する
5. PC での快適な閲覧を最優先としつつ、スマホからも最低限のデータ確認を可能にする

### 非ゴール

1. スプレッドシートへのデータ書き戻し・編集機能は提供しない
2. メール通知、Slack連携などの外部通知機能は含まない
3. 予測分析や AI による営業提案機能は含まない
4. 多言語対応（日本語のみ）
5. 本番クラウド環境へのデプロイ・運用設計は含まない

---

## 3. ユーザーストーリー

1. **管理者**として、月別の売上サマリーを一目で把握するために、年月を選択して月別サマリーを閲覧したい
2. **管理者**として、各営業担当者のパフォーマンスを比較するために、担当者別 KPI テーブルを閲覧したい
3. **管理者**として、どのイベントが成果を出しているか判断するために、イベント名別の集計を閲覧したい
4. **管理者**として、導線種別ごとの ROI を把握するために、導線種別の集計およびその中のイベント別サブテーブルを閲覧したい
5. **管理者**として、担当者と導線の相性を分析するために、担当者 x 導線種別のクロス集計マトリクスを閲覧したい
6. **管理者**として、個別のアポイントメント状況を確認するために、アポ一覧を年月フィルタ付きで閲覧したい
7. **管理者**として、プレゼン案件の進捗を確認するために、プレ一覧を閲覧したい
8. **管理者**として、トスアップ案件の状況を確認するために、トスアップ一覧を閲覧したい
9. **管理者**として、成約済み案件と契約書の管理状況を確認するために、成約一覧を閲覧したい
10. **営業担当者**として、自分を含むチーム全体の実績を確認するために、各ダッシュボードビューを閲覧したい
11. **管理者**として、最新のスプレッドシートデータを反映した数値を見るために、データが自動同期されていてほしい
12. **営業担当者**として、外出先から実績を確認するために、スマホのブラウザでも最低限の数値を閲覧したい
13. **管理者**として、計上日基準とアポ日基準の両方で売上を把握するために、2つの基準での売上集計を切り替えて閲覧したい
14. **管理者**として、安全にデータを管理するために、ログインしていないユーザーにはデータを表示しないでほしい

## 4. 機能一覧

### F01: ユーザー認証
**説明**: ユーザーがログインしてアプリにアクセスする機能。管理者と営業担当者の2つのロールを持ち、未認証のユーザーはすべてのページにアクセスできない。ログアウト機能も含む。

**受け入れ基準**:
- 未認証状態でいずれかのページにアクセスするとログイン画面にリダイレクトされる
- 正しい認証情報でログインするとダッシュボードに遷移する
- 誤った認証情報ではエラーメッセージが表示されログインできない
- ログアウトボタンを押すと認証状態が解除されログイン画面に戻る
- セッションがブラウザを閉じても一定期間保持される

**優先度**: P0

---

### F02: Google スプレッドシートデータ同期
**説明**: 指定された Google スプレッドシート（ID: `1bWbzZRcxGpUlXFOlTZlzlPQjC4v6MYKM9MZHRb-WA3A`）から全テーブル（アポ一覧、プレ一覧、トスアップ一覧、成約一覧、各マスタ）のデータを読み取り専用で取得し、アプリ内で利用可能な状態にする。スプレッドシートは絶対に変更しない。

**受け入れ基準**:
- アプリ起動時にスプレッドシートの全シートからデータを取得できる
- 定期的（最大5分間隔）に自動でデータを再取得し最新状態を反映する
- スプレッドシートへの書き込みは一切行わない
- データ取得に失敗した場合、最後に取得できたデータを表示し続け、エラー状態をユーザーに通知する
- 最終同期日時がヘッダーに表示される

**優先度**: P0

### F03: 年月フィルタ
**説明**: すべての集計ビューおよび一覧ビューに対して、年月プルダウンで表示対象の期間を切り替える機能。アポ予定日を基準にフィルタリングする。現在のスプレッドシートと同じ UX を維持する。

**受け入れ基準**:
- 年月プルダウンがすべてのビューの上部に配置されている
- デフォルトで現在の年月が選択されている
- 年月を変更すると、対応するビューのデータが即座に切り替わる（体感1秒以内）
- データに存在する全ての年月が選択肢として表示される
- フィルタリングはアポ予定日を基準とする

**優先度**: P0

---

### F04: 月別サマリービュー
**説明**: 年月ごとに営業 KPI を一覧表示するビュー。計上売上、入金済売上、未入金売上（計上日基準・アポ日基準の2パターン）、入金率、アポ予定数、アポ消化件数、アポ着座件数、アポ着座率、無効アポ数、ブリッジ数、残ブリッジ数、決着数、成約件数、決着成約率、計上売上見込、入金売上見込、クーリングオフ件数、クーリングオフ込み成約件数、クーリングオフ率を集計する。

**受け入れ基準**:
- 上記すべての KPI が年月ごとにテーブル形式で表示される
- 計上日基準とアポ日基準の2パターンの売上が明確に区別して表示される
- 数値は3桁区切りの日本円表記で表示される（売上系）
- 率は小数点以下1桁のパーセント表記で表示される
- 年月フィルタで選択した期間のデータが表示される

**優先度**: P0

### F05: 営業担当者別ビュー

**受け入れ基準**:
- 担当者ごとに1行ずつ KPI が表示される
- 月別サマリーと同じ KPI 項目に加え、目標売上と見込目標達成率が含まれる
- 目標売上はマスタ - 担当者から取得される
- 年月フィルタで期間を切り替えられる
- 全体の合計行が表示される

**優先度**: P0

### F14: レスポンシブ対応
**説明**: PC での快適な閲覧を最優先としつつ、スマホのブラウザでも主要な数値を確認できるレイアウト対応。

**受け入れ基準**:
- デスクトップ（1280px以上）で全テーブルが横スクロールなしに収まる
- タブレット（768px〜1279px）ではテーブルが横スクロールで閲覧可能
- スマホ（767px以下）ではナビゲーションがハンバーガーメニューに変わり、テーブルが横スクロールで閲覧可能
- いずれの画面幅でもテキストが読める大きさを維持する

**優先度**: P1

**受け入れ基準**:

- ヘッダーに最終同期日時が「最終更新: YYYY/MM/DD HH:mm」の形式で表示される
- 手動リフレッシュボタンを押すと即座にデータを再取得する
- データ取得エラー時にエラーメッセージが表示される

**優先度**: P1

**優先度**: P1

## 5. スプリント分解

### スプリント 1: 最小動作アプリとデータ接続
**ゴール**: Google スプレッドシートからデータを取得し、アポ一覧を1画面で表示できるアプリが動作する

**含まれる機能**: F02（基本部分）, F09（基本部分）, F13（基本部分）

**完了の定義**:
- アプリをローカルで起動してブラウザからアクセスできる
- Google スプレッドシートからアポ一覧データが取得され画面に表示される
- テーブルにアポ一覧の全カラムが表示される
- ページ上部に最低限のナビゲーション（アプリ名とビュー名）が表示される

**依存関係**: なし

---

### スプリント 2: 年月フィルタと全一覧ビュー
**ゴール**: 年月フィルタでアポ一覧を絞り込みでき、プレ・トスアップ・成約の各一覧も閲覧できる

**完了の定義**:
- 年月プルダウンが表示され、選択するとアポ一覧が即座にフィルタリングされる

## 6. 品質基準（Evaluator 用）

1. **機能完全性**: 各スプリントの受け入れ基準の 100% がブラウザ上で動作確認可能であること
2. **重大バグ件数**: データの不整合、画面表示の破綻、認証バイパスに分類される重大バグが 0 件であること
3. **ページ表示速度**: 各ビューの初回データ表示が2秒以内に完了すること（ローカル実行環境、同期済みデータ前提）
4. **年月フィルタ応答速度**: 年月プルダウンの変更から表示更新完了まで1秒以内であること
5. **データ正確性**: 月別サマリーの各 KPI 数値が、元スプレッドシートの同じ条件で手動集計した値と一致すること（誤差0）
6. **レスポンシブ表示**: 画面幅 375px（スマホ相当）でも全ビューが操作可能（テーブルが横スクロールで全カラム到達可能、ナビゲーションが機能する）であること
7. **認証の有効性**: 未認証状態でいずれかのビューの URL に直接アクセスした場合、データが一切表示されずログイン画面にリダイレクトされること
8. **エラー耐性**: スプレッドシートとの接続が切れた状態でも、最後に取得したデータで全ビューが表示され、エラー通知がユーザーに表示されること

## 7. 用語集

| 用語 | 定義 |
|---|---|
| **アポ（アポイントメント）** | 見込み客との初回面談の予定。営業プロセスの起点 |
| **プレ（プレゼンテーション）** | アポ後に実施する商品・サービスの提案プレゼン |
| **トスアップ** | 初回アポ担当者から別の営業担当者（クローザー）へ案件を引き継ぐこと |
| **成約** | 見込み客が契約に至った状態 |
| **決着** | アポが最終結果（成約・失注・無効）に至った状態。ブリッジ（保留）を除く |
| **ブリッジ** | 結論が出ず、次回のアポを設定した保留状態 |
| **残ブリッジ** | ブリッジ状態のまま未決着のアポ件数 |
| **クーリングオフ** | 成約後に契約解除された案件 |
| **着座** | アポが実際に実施された（ノーショーや直前キャンセルではない）状態 |
| **導線種別** | 見込み客の流入経路の大分類（インフルエンサー協業、広告、AI x コンテンツ、その他） |
| **イベント名** | 導線種別の中の個別イベント・キャンペーン名 |
| **計上売上** | 契約が確定した売上金額 |
| **入金済売上** | 実際に入金が確認された売上金額 |
| **未入金売上** | 契約確定だが入金未確認の売上金額 |
| **計上日基準 / アポ日基準** | 売上をどの日付で月に帰属させるかの2つの集計方法。計上日基準は契約日で、アポ日基準はアポ予定日で月を判定する |
| **見込目標達成率** | 見込み売上が担当者の目標売上に対してどの程度達成されているかの割合 |
| **マスタ** | 選択肢やマスタデータを管理するシート（ステータス一覧、担当者一覧、導線一覧） |
| **KPI（Key Performance Indicator）** | 営業活動の成果を測る主要指標 |

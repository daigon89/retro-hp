## 発見したバグ

### バグ #1（major）: `02_compare_all.mjs` の `extractYearMonth` が loose regex を使用

- **重大度**: major（比較スクリプトにバグ、ただし**プロダクションアプリには非影響**）
- **概要**: 比較スクリプト内の `extractYearMonth` 関数が末尾 `$` なしの regex を使用しており、「2026/04/17(金)」「2026/04/18(土) 22:15-23:45」など日本語曜日・時刻範囲付き日付文字列を誤って 2026-04 として集計する
- **再現手順**: スクリプト 02 の `extractYearMonth("2026/04/18(土) 22:15-23:45")` → "2026-04" を返す
- **影響**: 2026-04 のアポ予定数が実際には source=427（標準書式）なのに、スクリプトが app=434〜458 と誤算出する（31 行の過剰カウント）
- **プロダクションへの影響**: **なし** — プロダクション `filterUtils.ts` の `extractYearMonth` は正しく末尾 `$` を持つ strict regex を使用しており、曜日付き日付を正しく除外している
- **修正方法（スクリプト）**: `02_compare_all.mjs` の `extractYearMonth` regex を `filterUtils.ts` と同じ `/^(\d{4})[\/\-](\d{1,2})[\/\-]\d{1,2}(?:\s[\d:]+)?$/` に更新する

### バグ #2（minor）: 導線別分析シートの構造変化に比較スクリプトが未対応

- **重大度**: minor（スクリプト誤読）
- **概要**: 導線別分析シートに 広告・その他 の 2 行目（サブカテゴリ区切り行と推測）が存在し、比較スクリプトがこれを「channel=広告 で sheet=0」として誤検出。20 件の偽陽性不一致を生成
- **プロダクションへの影響**: **なし** — プロダクションアプリは導線別分析シートを参照しない
- **修正方法（スクリプト）**: `02_compare_all.mjs` の 導線別 パース部分に、`sheetVal === 0 かつ appVal > 1` の行を除外するフィルターを追加する

### バグ #3（minor）: 統合マスタに非標準書式の日付が 31 行存在

- **重大度**: minor（データ品質問題）
- **概要**: 統合マスタの アポ予定日 列に「2026/04/17(金)」「2026/04/18(土) 22:15-23:45」などの日本語曜日・時刻範囲付き文字列が 31 行存在する（2026-04 のみ）
- **影響**: プロダクションアプリはこれらを正しく除外（filterUtils.ts の strict regex）。シートの COUNTIFS もテキスト vs 数値比較で除外。両者が一致して除外しているため、不一致の原因にはならない
- **推奨**: データ入力の標準化（曜日・時刻の除去）を実施するか、データ品質チェックを追加する

## 改善提案（合否に非影響）

1. **分析シートをブラウザで開いて手動再計算**: 現在の IMPORTRANGE データは source と同期済みだが、依存する SUMIFS/COUNTIFS 数式のキャッシュが古い。ブラウザでシートを開けば自動再計算が走り、大半の不一致が解消される見込み
2. **`02_compare_all.mjs` の修正**: loose regex バグを修正し、正確な「アプリ値」を算出できるようにする。また、導線別分析の 2 行目フィルターを追加する
3. **クロス集計シートの列参照バグ修正（シート側）**: 広告チャネルで「成約 > 決着」という論理矛盾が 2026-03 に多数発生。`データシート(統合マスタ)` の列参照（$B:$B, $E:$E 等）がズレている可能性が高い
4. **川畑 亮輔のクーリングオフ計算バグ修正（シート側）**: 担当者別分析で クーリングオフ込み成約件数=-2、クーリングオフ率=200% という異常値が発生。シートの参照範囲を確認・修正する
5. **統合マスタの日付書式統一**: 曜日付き・時刻範囲付き日付（31 行）を標準形式（YYYY/MM/DD）に修正する

## 技術的付記

### IMPORTRANGE 鮮度差の正確なメカニズム

スクリプト実行中（約 4〜10 秒の間）にも IMPORTRANGE が更新されており、同じ 2026-04 アポ予定数が 386（script 02 実行時）→ 410（script 06 実行時）と変化した。これは IMPORTRANGE データキャッシュ更新と SUMIFS 数式キャッシュ更新が非同期であることを示している。raw IMPORTRANGE データ（script 04 で確認）は source と既に同期済みだが、それに依存する計算式セルの値は古いまま。ブラウザで開く→自動再計算、が解決策。

### 比較スクリプト vs プロダクションアプリの差異

| 項目 | `02_compare_all.mjs`（スクリプト） | プロダクションアプリ（`sheets.ts` + `filterUtils.ts`） |
|-----|----------------------------------|------------------------------------------------------|
| データ取得 | `UNFORMATTED_VALUE`（数値シリアルで取得） | デフォルト（`FORMATTED_VALUE`、書式済み文字列で取得） |
| `extractYearMonth` regex | loose（末尾 `$` なし） → **バグ** | strict（`(?:\s[\d:]+)?$` あり）→ **正しい** |
| 曜日付き日付の扱い | 誤ってカウント（2026-04 で +7〜31 過剰） | 正しく除外 |
| クロス集計 決着数 | 旧ロジック（`["成約","失注"]` のみ） | **新ロジック**（bridge+10日含む、crossUtils.ts 修正済み） |

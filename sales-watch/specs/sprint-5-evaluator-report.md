## 発見したバグ

### Bug 1

**重大度**: minor

**概要**: /event と /channel の合計値が、月別サマリーの合計値と一致しない

**再現手順**:
1. `http://localhost:3000/summary?ym=2026-04` を開く → 計上売上 ¥66,330,000、アポ予定数414を確認
2. `http://localhost:3000/event?ym=2026-04` を開く → 合計行の計上売上 ¥64,350,000、アポ予定数414を確認
3. `http://localhost:3000/channel?ym=2026-04` を開く → 合計行の計上売上 ¥66,330,000、アポ予定数411を確認

**期待動作**: 同一年月で集計した場合、/event・/channel の合計行が /summary の値と一致する（ゼロ誤差）

**実動作**:
- /event の計上売上: ¥64,350,000（/summary より ¥1,980,000 少ない）。原因はイベント名が null/空のレコードが除外されるため
- /channel のアポ予定数: 411（/summary より3件少ない）。原因は導線種別が null/空のレコードが除外されるため

**証拠**: curl コマンドで取得した HTML テキストから数値を直接確認

**備考**: スペック品質基準 #5「データ正確性」は「月別サマリーの各 KPI 数値」についての規定であり、/event・/channel ページは対象外。Sprint 5 の DoD（完了定義）にも合計値の一致要件なし。このため合否に影響しないが、将来的なデータ整合性の観点から修正を推奨。

## 改善提案

1. **「全期間」表示時の合計値一致**: ym="" (全期間) で /event・/channel を表示した場合、イベント名や導線種別が null/空のレコードを除外する現行ロジックにより、それらのレコードが合計に含まれない。「その他」「未設定」カテゴリとして集約する処理を追加すると、合計値の一貫性が向上する。

2. **展開ボタンの視覚的なヒント**: 現在「▶ で展開してイベント別サブテーブルを表示」というヒントテキストがページ先頭にあるが、初見ユーザーには気づきにくい可能性がある。ボタンにホバー時のアニメーションや tooltip を追加することで UX が向上する。

3. **展開状態の URL 保持**: 現在、ページをリロードすると展開状態がリセットされる（useState のため）。深い分析中にリロードした際の利便性のために、展開状態を URL の hash や searchParams に保存することを検討できる。
